# ParsYa Ads — библиотека рекламных креативов

Фронтенд сервиса для маркетологов: поиск рекламных креативов по ИНН рекламодателя, названию компании, домену или тексту объявления. Один и тот же креатив, показанный под разными `campaign_id`/площадками, собран в одну карточку.

## Файлы

- `index.html` — вход (email/пароль). Логинится в бэкенд [`parsya-control`](https://github.com/dimamarketing001-netizen/parser) через `POST /api/v1/auth/login` и сохраняет выданный токен в `localStorage`.
- `ad-intelligence.html` — основное приложение, четыре вкладки:
  - **Библиотека** — поиск, фильтры (площадка, статус распознавания, диапазон дат, «только с раскрытым ИНН», сортировка), карточки креативов, карточка рекламодателя с группировкой по `content_fingerprint`, детальная панель с campaign/banner/client ID и историей обнаружений. Каждую карточку можно сохранить в подборку.
  - **Сканирования** — пользователь сам запускает сбор данных под свой город/запрос (`POST /api/v1/runs`), видит список своих запусков со статусом и живым прогрессом (воркер синхронизирует частичные результаты каждые ~20 секунд, не только по завершении), может перейти из конкретного запуска прямо в отфильтрованную библиотеку по его результатам.
  - **Подборки** — пользовательские списки сохранённых креативов (`/api/v1/collections*`) — например «Конкуренты» или «Удачные офферы»; создание, просмотр, удаление подборок и отдельных креативов внутри них.
  - **Источники и качество** — реальная статистика по площадкам (`GET /api/v1/coverage`): сколько креативов распознано полностью/частично, у скольких найден рекламодатель (ИНН), когда площадка собиралась последний раз — без макетных чисел.
  - Шестерёнка в хедере — смена пароля своего аккаунта.
- `docs/` — черновые UX-заметки из первой, чисто визуальной версии макета; оставлены для истории, текущий интерфейс проще их и ориентируется на один реальный продукт, а не пять демонстрационных пространств.

## Запуск локально

Это статические файлы, без сборки:

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080/index.html`. По умолчанию приложение обращается к продакшн-бэкенду ParsYa; на экране входа есть поле «Другой адрес сервиса» — впишите туда адрес своего тестового `parsya-control`, если нужно.

## Как это подключено к бэкенду

- Бэкенд (отдельный репозиторий `parser`/`parsya-control`) должен быть запущен с переменной `PARSYA_FRONTEND_ORIGINS`, включающей origin, с которого открыт этот фронтенд (иначе браузер заблокирует запросы по CORS).
- Учётные записи маркетологов создаёт администратор на странице «Пользователи SaaS» (`/admin/users`) в консоли `parsya-control` — отдельно от обычного логина администратора этой консоли.
- Роль `admin` в выданном токене добавляет в этом приложении ссылку на консоль администратора (`/admin/users`) — для входа туда нужен отдельный пароль оператора, это разные системы авторизации.

## Статус

Рабочее приложение, подключённое к реальному API (`/api/v1/*`). Авторизация, поиск, фильтры, группировка по рекламодателю/ИНН, запуск сканирований со своими параметрами, живой прогресс и смена пароля проверены end-to-end (включая браузерный прогон) на тестовых данных. Управление учётными записями пользователей осталось задачей администратора в консоли `parsya-control` (`/admin/users`), не этого фронтенда.
