# ParsYa Ads — библиотека рекламных креативов

Фронтенд сервиса для маркетологов: поиск рекламных креативов по ИНН рекламодателя, названию компании, домену или тексту объявления. Один и тот же креатив, показанный под разными `campaign_id`/площадками, собран в одну карточку.

## Файлы

- `index.html` — вход (email/пароль). Логинится в бэкенд [`parsya-control`](https://github.com/dimamarketing001-netizen/parser) через `POST /api/v1/auth/login` и сохраняет выданный токен в `localStorage`.
- `ad-intelligence.html` — основное приложение: поиск, карточки креативов, карточка рекламодателя с группировкой по `content_fingerprint`, детальная панель с campaign/banner/client ID и историей обнаружений.
- `docs/` — черновые UX-заметки из первой, чисто визуальной версии макета; оставлены для истории, текущий интерфейс проще их и ориентируется на один реальный продукт, а не пять демонстрационных пространств.

## Запуск локально

Это статические файлы, без сборки:

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080/index.html`. По умолчанию приложение обращается к продакшн-бэкенду ParsYa; на экране входа есть поле «Другой адрес сервиса» — впишите туда адрес своего тестового `parsya-control`, если нужно.

## Как это подключено к бэкенду

- Бэкенд (отдельный репозиторий `parser`/`parsya-control`) должен быть запущен с переменной `PARSYA_FRONTEND_ORIGINS`, включающей origin, с которого открыт этот фронтенд (иначе браузер заблокирует запросы по CORS).
- Учётные записи маркетологов создаёт администратор на странице «Пользователи SaaS» (`/admin/users`) в консоли `parsya-control` — отдельно от обычного логина администратора этой консоли.
- Роль `admin` в выданном токене добавляет в этом приложении ссылку на консоль администратора (`/admin/users`) — для входа туда нужен отдельный пароль оператора, это разные системы авторизации.

## Статус

Рабочее приложение, подключённое к реальному API (`/api/v1/*`). Авторизация, поиск, группировка по рекламодателю/ИНН и детальная панель проверены end-to-end (включая браузерный прогон) на тестовых данных. Два пункта, которые по дизайну сервиса намеренно не реализованы здесь: запуск сканирований и управление пользователями — это задачи администратора в консоли `parsya-control`, не этого фронтенда.
